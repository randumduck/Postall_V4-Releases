Self-hosted deployment

Control your deployment. Own the operational work.

The included scripts run Postall in Docker and store application data in a named volume on the Docker host. Self-hosting gives you control over that environment, but security depends on how you secure, expose, update, and back it up. This page also loads styling and icons from third-party CDNs, and connected services have their own data flows.

  • Persistent volume: The setup scripts mount postall_data at /app/data.
  • Backups matter: Protect the Docker volume before replacing containers or maintaining the host.
  • Limit exposure: Keep credentials secure and avoid exposing the app publicly without access controls.

Deploy Postall Today

Choose an operating system to download the setup script. Review it before running; Docker must be installed and running.

Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/randumduck/Postall_V4-Releases/main/setup_postall.ps1' -OutFile 'setup_postall.ps1'

After reviewing the file, run .\setup_postall.ps1 in PowerShell or bash setup_postall.sh in a terminal.
